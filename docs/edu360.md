## Post-MVP — Feature Roadmap

### Phase 1: Real Listings & Applications (next sprint)

#### Database tables needed
```sql
-- Institution profiles (one per registered institution account)
CREATE TABLE edu360_institutions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID REFERENCES users(id),
  name            VARCHAR(200) NOT NULL,
  type            VARCHAR(50),          -- school/college/university/coaching/online/vocational
  city            VARCHAR(100),
  state           VARCHAR(100),
  affiliation     VARCHAR(100),
  programs        JSONB DEFAULT '[]',   -- array of program names
  fee_min         INTEGER,
  fee_max         INTEGER,
  seats           INTEGER,
  mode            VARCHAR(20),          -- offline/online/hybrid
  description     TEXT,
  phone           VARCHAR(20),
  email           VARCHAR(200),
  established     INTEGER,
  accreditation   VARCHAR(100),
  is_verified     BOOLEAN DEFAULT FALSE,
  is_active       BOOLEAN DEFAULT TRUE,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

-- Student applications to institutions
CREATE TABLE edu360_applications (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id  UUID REFERENCES edu360_institutions(id),
  student_name    VARCHAR(200),
  student_email   VARCHAR(200),
  student_phone   VARCHAR(20),
  program_sought  VARCHAR(200),
  profile_data    JSONB,               -- transcript data from AI extraction
  documents       JSONB DEFAULT '[]',  -- array of uploaded doc URLs
  status          VARCHAR(30) DEFAULT 'pending', -- pending/reviewed/shortlisted/rejected/offered/enrolled
  counselor_notes TEXT,
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);

-- Lead / enquiry tracking (CRM)
CREATE TABLE edu360_leads (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id  UUID REFERENCES edu360_institutions(id),
  student_name    VARCHAR(200),
  student_email   VARCHAR(200),
  student_phone   VARCHAR(20),
  source          VARCHAR(50),          -- web/whatsapp/referral/direct
  program_interest VARCHAR(200),
  status          VARCHAR(30) DEFAULT 'new', -- new/contacted/counselled/applied/converted/lost
  assigned_to     VARCHAR(200),         -- counselor name/email
  next_followup   DATE,
  notes           TEXT,
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);
```

#### API endpoints needed (backend)
```
POST   /v1/edu360/institutions                  -- register institution
GET    /v1/edu360/institutions                  -- list (paginated, filtered)
GET    /v1/edu360/institutions/:id              -- detail
PUT    /v1/edu360/institutions/:id              -- update (auth: institution owner)
POST   /v1/edu360/institutions/:id/apply        -- student applies
GET    /v1/edu360/institutions/:id/applications -- institution views applications (auth)
PUT    /v1/edu360/applications/:id/status       -- update status (auth: institution)
POST   /v1/edu360/leads                        -- record enquiry as lead
GET    /v1/edu360/leads                        -- institution's CRM view (auth)
PUT    /v1/edu360/leads/:id                    -- update lead status
```

### Phase 2: CRM & Lead Management

- **Counselor dashboard**: Assigned leads list with follow-up dates, call notes, status pipeline
- **Lead pipeline view**: Kanban board — New → Contacted → Counselled → Applied → Converted / Lost
- **Bulk import leads**: CSV upload for offline enquiry data
- **WhatsApp / SMS triggers**: Auto-message on lead status change
- **Lead assignment**: SuperAdmin assigns counselors to institutions; counselors see only their leads
- **Follow-up reminders**: Email/in-app alerts for overdue follow-ups

---

### Phase 3: Admissions Workflow

- **Online application form builder**: Institution configures required fields per program
- **Document uploads**: Student uploads marksheets, ID proof, photos to S3/Cloudinary
- **Multi-step status tracking**: Applied → Document Verified → Written Test → Interview → Offer Letter → Enrolled
- **Offer letter generation**: PDF offer letter template with institution branding
- **Seat matrix**: Real-time available seats per program with reservation category breakdown
- **Waitlist management**: Auto-promote waitlisted students when seat opens

---

### Phase 4: Payments & Fees

- **Fee structure configuration**: Institution sets fee components (tuition, hostel, lab, exam)
- **Online payment gateway**: Razorpay / PayU integration for application fee and tuition fee
- **Payment receipt**: Auto-generate PDF receipt on successful payment
- **Fee reminders**: Automated reminders for upcoming due dates
- **Scholarship management**: Define scholarships with eligibility criteria, auto-apply discounts

---

### Phase 5: Placement Management

- **Placement board**: Employers post campus placement drives; students apply
- **Student placement profile**: Resume, CGPA, skills, placement preference (city, function, salary)
- **Drive management**: Institution schedules drives, students register, employers shortlist
- **Offer tracking**: Offer letter upload, CTC recording, placed/unplaced status
- **Placement analytics**: Placement rate, avg CTC, top recruiters, sector-wise breakdown

---

### Phase 6: Analytics & Reporting

- **Institution analytics**: Applications received, conversion rate, source analysis, program-wise seats filled
- **SuperAdmin dashboard**: Platform-wide stats — total institutions, students, applications, placements
- **Student journey analytics**: Drop-off funnel from search → enquiry → application → enrollment
- **Counselor performance**: Leads handled, conversion %, avg response time
- **ROI reports**: Cost per lead, cost per enrollment for marketing spend

## Architecture Notes

### Auth strategy (MVP vs future)
| Layer | MVP | Future |
|---|---|---|
| Student/parent | localStorage (`edu360_session`) | Backend JWT + `edu360_users` table |
| Institution | localStorage | Backend JWT + `users` table with `role = institution` |
| Counselor | N/A | Backend JWT + RBAC (`role = counselor`) |

### AI usage
| Use case | API | Notes |
|---|---|---|
| Transcript extraction | `/api/extract-transcript` | Claude → Gemini fallback |
| Resume extraction (jobs) | `/api/extract-resume` | Same pattern |
| Program recommendation | Future — `/api/edu360/recommend` | Student profile → match institutions |
| Application screening | Future | Institution sets criteria; AI scores applications |

### Storage strategy
| Data | MVP | Future |
|---|---|---|
| Student academic profile | localStorage JSON | PostgreSQL `edu360_students` table |
| Institution listings | Mock data (hardcoded) | PostgreSQL `edu360_institutions` table |
| Applications | Email notification only | PostgreSQL `edu360_applications` table |
| Documents | Not stored | S3 / Cloudinary |
| Platform config | `platform_config` table | Same — no change needed |
